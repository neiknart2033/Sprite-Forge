1. PROJECT OVERVIEW & EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
1.1. Mission Statement
Sprite-Forge is an open, browser-native toolkit that bridges the gap between 
game programmers and 2D visual artists. It provides bidirectional asset workflows:
1. UNPACK (Slicing): Splitting composite sprite sheets into standalone frames 
   via fixed grid or alpha-based auto-detection.
2. PACK (Atlas Packing): Packing heterogeneous individual frames into a compact, 
   memory-efficient texture atlas using optimal 2D Bin Packing algorithms 
   (MaxRects) with transparent trimming, pivot preservation, and texture-bleeding 
   guards.

1.2. Key Architectural Tenet: Zero Backend (100% Client-Side)
- All computations, image manipulation, packing heuristics, and file packaging 
  execute entirely inside the user's browser via HTML5 Canvas, OffscreenCanvas, 
  and Web Workers.
- Hosting can be served completely from global CDNs (Cloudflare Pages, Vercel, 
  or Netlify) at zero ongoing infrastructure cost, maximizing ad revenue margins.

2. USER PERSONAS & DUAL-AUDIENCE DESIGN CRITERIA
--------------------------------------------------------------------------------
Sprite-Forge bridges two distinct user groups through a "Progressive Disclosure" 
UX model with an immediate toggle: [Artist Mode] <---> [Developer Mode].

2.1. Persona A: The Visual Artist & 2D Animator
- Core Needs:
  * Crisp, unblurred display of pixel art (nearest-neighbor scaling).
  * Smooth timeline & animation preview controls (custom FPS, loop, ping-pong).
  * Preservation of animation registration/pivot points when trimming empty space.
  * Direct exports to shareable formats (Animated GIF, APNG) without command-line tools.
- Friction Points to Avoid:
  * Blurry bilinear filtering when inspecting pixel assets.
  * Complex, cryptic configuration fields exposed on first load.

2.2. Persona B: The Game Programmer & Engine Specialist
- Core Needs:
  * Strict memory optimization (Power-of-Two textures: 512, 1024, 2048, 4096).
  * High packing density (>90% fill rate) via heuristic 2D bin packing.
  * Texture extrude / padding options to eliminate WebGL texture bleeding artifacts.
  * Ready-to-import metadata exports (JSON Hash/Array for Phaser, Godot .tres, 
    Unity metadata, CSS Sprites).
- Friction Points to Avoid:
  * Inflexible, non-standard JSON formats requiring custom parsing scripts.
  * Inability to fine-tune spacing and rotation rules.

4. SYSTEM ARCHITECTURE & TECH STACK
--------------------------------------------------------------------------------
4.1. Core Technology Stack
- Framework: Next.js 14 (App Router) or Vite + React 18 / TypeScript
  (Next.js provides Static Site Generation for maximum SEO indexing).
- Styling & Components: Tailwind CSS + Lucide Icons + Radix UI primitives.
- Rendering Engine: HTML5 Canvas Context 2D + OffscreenCanvas.
- Client-Side Archival: JSZip (for multi-asset ZIP bundles) + FileSaver.js.
- GIF Generation: `omggif` or `gifshot` (compiled client-side GIF encoder).
- State Management: Zustand (lightweight, zero-boilerplate state store).

4.2. Algorithmic Modules

A. Unpack Module (Sheet Slicer):
   1. Uniform Grid Mode:
      - Traverses image via specified Frame Width (W), Frame Height (H), 
        Margin X/Y, and Spacing X/Y.
      - Optional "Discard Empty Frames" pass checking pixel alpha values.
   2. Alpha Auto-Detect Mode:
      - Scans `ctx.getImageData()` for pixels with Alpha > Threshold (default: 10).
      - Executes Breadth-First Search (BFS) / Connected-Component Labeling (CCL)
        to identify disjoint pixel clusters and calculate minimum bounding boxes.

B. Pack Module (Optimal 2D Texture Packer):
   1. Heuristic Pre-sorting:
      - Sort incoming blocks by Maximum Dimension: `Math.max(w, h)` descending,
        or Area: `w * h` descending.
   2. Packing Heuristics:
      - Primary Algorithm: MaxRects (Maximal Rectangles) using Best Short Side 
        Fit (BSSF) and Best Area Fit (BAF).
      - Fallback / Lightweight Algorithm: Binary Tree Bin Packing for fast previews.
   3. Alpha Trimming with Anchor Retention (Pivot Preservation):
      - Strips empty transparent pixels to save atlas real estate.
      - Retains original offset coordinates (`spriteSourceSize` vs `sourceSize`) 
        so game engine runtimes reconstruct animations without jitter.
   4. Texture Bleed Prevention (Extrude & Padding):
      - Padding: Configurable transparent spacer (1px - 8px) between rects.
      - Extrude: Duplicates edge pixels 1px outwards to prevent color leaking 
        during linear texture filtering and mipmapping.

- Godot 4 Atlas: Texture atlas resource mapping (`.tres` definitions).
- Web CSS Sprites: Generated CSS class definitions with `background-position`.
